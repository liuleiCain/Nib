# 架构

## 前端

- `src/app/App.tsx`：当前窗口的工作区、标签列表、保存流程、未保存确认、快捷键、命令面板，以及项目打开、标签恢复与记录。
- `src/features/projects/`：最近项目列表和工具栏项目菜单。
- `src/features/editor/`：CodeMirror 状态、高亮和单个 `EditorView`。每个标签保留独立的 `EditorState`，切换不重读文件，撤销栈不丢失。
- `src/features/explorer/`：按需展开目录、加载/错误/重试状态、手动刷新，以及按外部变化重读已加载目录；按 Git 状态为文件名着色；右键菜单（`ContextMenu`）与名称输入框（`NameDialog`），菜单项由 `App.tsx` 按条目类型和 Git 状态生成。
- `src/features/git/`：提交面板（`CommitPanel`）、Diff 视图（`DiffView`，基于 `@codemirror/merge`）和编辑器行号旁的变更标记（`changes.ts`）。
- `src/lib/backend.ts`：类型明确的 Tauri IPC 边界；浏览器预览明确禁用本地目录入口。
- `src/styles/global.css`：深色主题变量、布局、焦点与缩放适配。

没有状态管理库和组件库。图标按需使用 Lucide。语言包通过动态导入拆分，单个编辑视图控制 DOM 数量。

## Rust

- `workspace`：按窗口标签登记工作区，每个窗口保存项目根路径与单调递增的工作区 id；切换后拒绝旧请求。同一项目只允许一个窗口打开。
- `window`：按 `tauri.conf.json` 窗口模板创建 `window-N` 窗口，聚焦已有窗口，窗口销毁后释放工作区。macOS 上每个项目仍是独立的原生窗口，但通过 `tabbingIdentifier` 与 `addTabbedWindow:ordered:` 并入当前聚焦窗口的标签组，表现为同一窗口顶部的项目标签；新窗口先隐藏创建，在主线程并入后再显示。并入失败时作为独立窗口显示。Windows/Linux 为独立窗口。
- `session`：最近项目、退出时打开的项目及各项目标签，写入用户目录下的 `~/.nib/session.json`（Windows 为 `%USERPROFILE%\.nib\session.json`），带版本号，同目录临时文件原子替换。文件缺失、损坏或版本不符时从空会话开始，不影响项目文件。退出 Nib 后删除 `~/.nib` 即可清空最近项目与恢复记录。
- `filesystem`：目录枚举、UTF-8 校验、读取限制、换行/BOM 检测、版本冲突检查、原子保存；新建空文件/目录（`create_new` 不覆盖）、未跟踪条目的重命名、移到废纸篓（`trash` crate，macOS 用系统文件管理接口，不需要“自动化”授权）、在访达/资源管理器中显示。路径经 `Workspace::entry` 校验：只解析父目录，末级符号链接操作链接本身，不跟随到项目外。
- `git`：调用本机 Git CLI 读取仓库状态、文件的 HEAD 版本，并执行勾选提交，见下文。
- `commands`：命令参数与返回类型；文件系统和 Git 操作通过 `spawn_blocking` 执行。
- `error`：结构化错误码和中文错误说明。

每个窗口的工作区互斥锁使该窗口内读写与切换串行，避免旧工作区写入新项目；不同窗口互不阻塞。前端额外丢弃旧项目返回的数据。没有全项目扫描或文件轮询；唯一的后台常驻任务是下述项目目录监听。

## 实时刷新与自动保存

- `watcher`：每个窗口的项目用 `notify`（macOS 为 FSEvents）递归监听项目根目录。打开、替换项目时重建监听，关闭项目或窗口时释放；监听线程随监听器释放退出。
- 事件按 150 ms 窗口合并，忽略 `.git`、`node_modules`、`target`、`.DS_Store` 及项目外和非 Unicode 路径，只通过 `nib://files-changed` 发给拥有该项目的窗口，并带上工作区 id，前端丢弃旧项目的事件。单批超过 500 个路径或监听报告需重扫时，只通知整体刷新。
- 文件树：重读变化路径的父目录及其自身中已加载过的目录；读取期间再次变化会在完成后补读一次，刷新时保留旧列表避免闪烁。
- 已打开标签：读取磁盘内容后按 SHA-256 版本比较。版本未变（包括自己保存产生的事件）不处理；标签无未保存编辑时以最小替换区间就地更新，外部写入不进入撤销历史；有未保存编辑且磁盘已变时标记暂停（`paused`），不覆盖任何一方；文件被删除（后台错误码 `NOT_FOUND`，如切换分支、`git rm`）时，无未保存编辑的标签直接关闭，与 GoLand 一致；有未保存编辑的标签保留内容、暂停并提示。文件变为不可编辑时同样保留编辑并暂停。正在保存的标签等保存完成后再同步。
- 自动保存：停止输入 1 秒、切换标签、窗口失去焦点时保存未暂停的标签；关闭标签和退出前先静默保存，只对暂停或保存失败的文件弹出确认。保存始终走原有的版本检查与原子替换，失败即暂停该标签，手动保存成功或重新加载后恢复。

## Git

- 调用：`std::process::Command` 以参数数组启动 `git`，不经过 Shell；全局加 `--literal-pathspecs` 使 `*`、`?` 等字符按字面匹配；`GIT_TERMINAL_PROMPT=0`、`GIT_EDITOR=true` 禁止交互。读取超时 20 秒，提交超时 300 秒（可能运行钩子）；超时结束进程，提交超时提示结果未知，不自动重试。标准输出按上限读取并丢弃多余部分，避免管道写满阻塞。
- 图形界面启动的应用拿不到登录 shell 的 PATH，提交钩子会找不到 Homebrew、nvm 等命令；首次调用 Git 时从 `$SHELL -ilc` 读取一次 PATH，与原 PATH 合并。
- 仓库识别：`rev-parse --show-toplevel --show-prefix --absolute-git-dir`（英文输出识别“非仓库”）。项目可以是仓库子目录，状态只统计项目目录（`-- .`），路径换算为相对项目根目录。
- 状态：`status --porcelain=v2 -z --branch --untracked-files=all`，NUL 分隔，正确处理空格、中文、换行文件名；解析分支、HEAD、上游与领先/落后数，以及修改、新增、删除、重命名（含原路径）、冲突和子模块。暂存区与工作区合并为一种状态。`.git` 下的 `MERGE_HEAD`、`rebase-*` 等标记识别进行中的操作。
- 文件版本：HEAD 侧先 `cat-file -t` 判断是否存在及是否为普通文件，再 `cat-file --filters` 按仓库换行与过滤规则转为工作区形式；工作区侧经工作区路径校验后读取。两侧都检查二进制、5 MiB 上限与 UTF-8，统一为 LF 并去掉 BOM，与编辑器一致。
- 提交：按仓库加互斥锁串行。勾选的未跟踪文件先 `add --intent-to-add`，再 `commit --only` 并通过 `--pathspec-from-file=- --pathspec-file-nul` 传入路径（重命名同时传新旧路径），提交信息用 `--message=` 传参。只有这些路径进入提交，其他文件的暂存状态不变。提交失败（含钩子拒绝）时 `rm --cached` 撤销登记，文件恢复为未跟踪。
- 刷新：监听器把项目根目录 `.git` 下 HEAD、索引、引用的变化（忽略 `objects`、`logs`）标记为 `git: true`；前端合并 400 ms 内的变化后刷新状态。只处理最新请求的结果，项目切换后丢弃。HEAD 变化时重读所有已打开标签的 HEAD 版本，否则只重读状态类型变化的文件；已打开的 Diff 内容变化时重建。项目是仓库子目录时监听不到 `.git`，窗口获得焦点时补一次刷新。
- 按块回滚：Diff 视图用 `@codemirror/merge` 的回滚控件把一块恢复为 HEAD 内容，计算出回滚后的全文交给 `App.tsx`，不新增 Git 命令。文件已打开时改动标签并走原有的版本检查保存（编辑器可撤销）；未打开时读取磁盘，确认内容与 Diff 一致后按原换行和 BOM 保存。有未保存编辑、正在保存或磁盘已变化时拒绝并重建 Diff，不覆盖其他改动。
- 加入版本控制：`git_add` 命令按仓库加锁后执行 `git add --pathspec-from-file=- --pathspec-file-nul`，只登记不提交，只接受项目内路径；写超时提示结果未知，不重试。
- 恢复已删除文件：`git_restore` 命令确认后执行 `git checkout HEAD -- 路径`，同时恢复该路径的暂存状态。按仓库加锁、拒绝进行中的合并/变基，持锁后再确认文件不存在，HEAD 中必须是普通文件；只接受项目内路径。写超时提示结果未知，不重试。
- 回滚（右键）：`git_rollback` 持锁后重新读取状态，不信任前端：修改、删除用 `restore --source=HEAD --staged --worktree` 恢复暂存区和工作区（丢弃修改），重命名同时传新旧路径（恢复原路径、移除新路径），新增只 `restore --staged` 取消登记、保留文件；未跟踪和冲突文件拒绝。前端确认框列出文件并说明会丢弃修改。
- 添加到 .gitignore：`git_ignore` 只接受不含已跟踪文件的路径（`ls-files` 检查），规则写入项目根目录 `.gitignore`，以 `/` 锚定、目录加 `/`、转义 `* ? [ \` 与末尾空格；已有规则不重复写入，沿用原有换行；`.gitignore` 不是普通文件时拒绝。
- 重命名：`rename_entry` 先校验名称与同名冲突，路径下有已跟踪文件时用 `git mv`（提交面板显示为重命名），否则直接改名；大小写不敏感的文件系统上允许只改大小写。
- 行号旁标记：`Chunk.build` 比较 HEAD 版本与当前文档，编辑时 `Chunk.updateB` 增量更新；超过 1 MiB 字符不计算。点击标记打开 CodeMirror tooltip，预览最多 12 行 HEAD 原内容；回滚用 HEAD 片段替换该块（`userEvent: "revert"`），进入撤销栈，不直接写盘。文档或 HEAD 变化、Esc、点击弹窗外时关闭；只读文件禁用回滚。
- 提交记录：`git_log` 执行 `log -z --decorate=full --format=…%x1f… --max-count=101 --skip=N HEAD -- .`，字段以 0x1F、记录以 NUL 分隔，多取一条判断是否还有下一页；只包含涉及项目目录的提交。仓库尚无提交时返回空列表。`%D` 按完整引用名区分当前分支、本地分支、远程分支和标签，忽略 `origin/HEAD`、stash 和游离 HEAD。前端用请求序号丢弃迟到的页，HEAD、分支或远程操作后从第一页重读。
- 提交详情与历史 Diff：哈希只接受 4–64 位十六进制，再用 `rev-parse --verify <哈希>^{commit}` 解析为完整提交，不接受 `HEAD`、选项或修订表达式。详情用 `show --no-patch` 读取信息，`diff-tree -r -z --name-status --find-renames --relative <第一个父提交> <提交>`（根提交用 `--root`）列出项目目录内的变更，最多 5,000 个文件。`git_commit_diff` 两侧都用与 HEAD 相同的 `cat-file -t` / `cat-file --filters` 读取（父提交侧取重命名前的路径），同样检查二进制、大小与编码。提交 Diff 标签的标识为「哈希 + NUL + 路径」，与工作区 Diff 共用标签栏和视图，只读、不提供回滚，不随工作区变化刷新，也不随文件改名移动。
- 分支：`git_branches` 用 `for-each-ref refs/heads` 读取本地分支、上游与 `upstream:track`（领先/落后/已删除），`remote -v` 读取远程地址并隐藏 URL 中的密码；当前分支由 `symbolic-ref` 读取，新仓库也能显示。远程分支用 `for-each-ref refs/remotes` 读取，跳过 `origin/HEAD` 等符号引用；远程名可能含 `/`，按已配置远程中最长的前缀拆分出远程名和分支名，已删除远程的残留记录不列出，最多 2,000 个。新建分支先拒绝以 `-` 开头和控制字符，再用 `check-ref-format refs/heads/<名称>` 校验，确认不存在后 `switch --create`；指定起点时只接受已存在的 `refs/heads/…` 或 `refs/remotes/…` 完整引用名，执行 `switch --no-track --create <名称> <起点>`。检出远程分支：远程须已配置、远程分支须存在，本地无同名分支时 `switch --track --create <名称> refs/remotes/<远程>/<分支>`，已有同名分支时只在其上游正是该远程分支时切换。重命名 `branch --move`（目标已存在时拒绝）。删除本地分支先 `branch -d`，英文输出识别 “not fully merged” 返回 `NOT_MERGED`，前端再次确认后 `branch -D`；不能删除当前分支。删除远程分支 `push <远程> --delete refs/heads/<分支>`，走远程命令的超时与错误提示。切换只接受已存在的本地分支（`show-ref --verify`），执行 `switch --no-guess`，不按远程分支自动新建；未提交修改冲突时由 Git 拒绝。两者按仓库加锁、拒绝进行中的合并/变基，写超时提示结果未知。前端切换前先保存所有未保存的编辑并锁定界面，之后靠目录监听与 Git 刷新同步标签。
- 远程：网络命令额外加 `-c credential.interactive=never`，沿用 `GIT_TERMINAL_PROMPT=0`，超时 180 秒；获取与拉取用英文输出识别错误，推送保留用户的语言环境（会运行 pre-push 钩子），拒绝标记 `[rejected]` 不随语言变化。认证、主机密钥、网络错误在 Git 原始说明前附加处理建议。获取为 `fetch --all`，没有远程时直接说明。拉取：确认当前分支与上游 → `fetch <远程>` → `merge-base --is-ancestor` 判断已是最新 / 可快进 / 已分叉（分叉时用 `rev-list --left-right --count` 给出双方提交数，不执行合并）→ `merge --ff-only --no-autostash @{upstream}`，不使用 `git pull`，不受 `pull.rebase` 配置影响。推送：有上游时 `push`；没有上游时须选择已配置的远程，执行 `push --set-upstream <远程> HEAD:refs/heads/<分支>`；上游已删除时按 `branch.<名称>.remote/merge` 配置推送。推送与拉取超时提示结果未知，不重试。获取与推送不锁定前端编辑，前端同一时间只进行一个远程操作；后台按仓库锁与其他 Git 写操作串行。
- 合并与变基（`src-tauri/src/git/merge.rs`）：目标只接受已存在的 `refs/heads/…`、`refs/remotes/…` 完整引用名，不能是当前分支。开始前按仓库加锁、拒绝进行中的操作，并用仓库根目录的 `status --porcelain --untracked-files=no` 要求已跟踪文件没有未提交修改，保证 `--abort` 能完整恢复。目标已是 HEAD 的祖先时返回 `upToDate`。合并为 `merge --no-edit --no-autostash --message=<信息> <引用>`，信息按 Git 默认格式用分支短名生成（直接传短名可能被同名标签抢先解析）；变基为 `rebase --no-autostash <引用>`。两者保留用户的语言环境运行钩子，超时 300 秒后提示结果未知。命令失败时若 `.git` 下仍有 `MERGE_HEAD` 或 `rebase-*`，返回 `stopped`，附 `diff --name-only -z --no-relative --diff-filter=U` 列出的冲突文件（转为相对项目根目录，最多列出 20 个）；没有冲突（如钩子失败）时附 Git 的说明；否则作为错误返回。
- 冲突处理：标记已解决 `git_resolve` 只接受项目内、确实未解决的冲突路径，未带 force 时检查文件开头 5 MiB 是否仍有成对的 `<<<<<<< `/`>>>>>>> ` 行，有则返回 `CONFLICT_MARKERS`；执行 `add --all`，删除的文件记为删除。`git_continue` 仍有冲突时直接返回 `stopped`，否则先在仓库根目录 `add --update`（开始时工作区干净，已跟踪文件的修改都来自解决冲突），合并执行 `commit --no-edit`（使用 `MERGE_MSG`），变基执行 `rebase --continue`；`GIT_EDITOR=true` 让 Git 不打开编辑器。`git_skip` 仅变基可用（`rebase --skip`），`git_abort` 执行 `merge --abort` 或 `rebase --abort`。这些命令持锁后再读取进行中的操作，拣选、还原等其他操作仍要求在终端处理。前端开始合并、变基和继续前先保存所有编辑，跳过与中止不保存（被丢弃的内容由外部修改检测保护）；暂停时切到提交面板并提示冲突文件。
- 配色：状态色定义为 `global.css` 的 `--git-*` / `--diff-*` 变量，与深色背景对比度不低于 3:1，按 Machado 色觉模拟检查红色盲、绿色盲、蓝色盲下两两可区分。颜色之外，提交面板与文件树用 M/A/D/R/C/U 字母，未跟踪斜体、删除删除线、冲突加粗，行号旁新增为实心条、修改为虚线条、删除为三角，Diff 左右分侧。

## 多窗口与会话恢复

1. 启动时读取 `session.json` 的打开列表，规范化后只为仍可访问的目录各建一个窗口，并登记为窗口待打开项目；没有可恢复项目时打开一个空窗口。
2. 窗口加载后调用 `window_startup` 取出待打开项目并打开，再按记录顺序从磁盘重新读取标签；单个文件失败时跳过并汇总提示。恢复完成前不覆盖标签记录。
3. 打开项目时若已有窗口打开同一规范化路径，只聚焦该窗口。已有项目的窗口再打开项目会新建窗口（macOS 上为新项目标签）；也可在项目菜单中显式替换当前窗口的项目。
4. 标签增减或切换时记录项目的标签路径和当前标签，编辑内容变化不写入；未保存内容不进入会话文件。
   窗口模板固定为深色外观（`"theme": "Dark"`），系统标题栏、原生项目标签栏和全屏时的顶部区域与界面深色主题一致，不随系统浅色模式变白。

5. 关闭单个窗口或关闭项目时，项目移出打开列表；退出应用（Cmd+Q）或关闭最后一个窗口时保留，下次启动恢复。退出过程中用户在某个窗口选择返回编辑，则按仍打开的窗口校正打开列表。
6. 会话文件只记录项目根目录与相对路径，不存储文件内容；最近项目最多 20 个，单个项目最多记录 30 个标签。

## 保存约束

1. 读取普通文件，先检查开头 8 KiB 是否含 NUL 以拒绝二进制，再拒绝非 UTF-8 和混合换行；超过 20 MiB 的文本只读取开头 5 MiB 作只读预览（参照 GoLand 默认 20 MB 加载上限），不可编辑和保存。
2. 保留原始磁盘字节的 SHA-256、换行风格和 UTF-8 BOM 状态；编辑器内部统一使用 LF。
3. 保存时序列化回原换行风格；验证磁盘哈希与打开或上次保存时一致。
4. 在目标文件同目录创建临时文件，写入、复制普通文件权限并 `sync_all`。
5. 替换前再次检查磁盘哈希，然后通过 `tempfile::persist` 原子替换目标。失败时临时文件随作用域清理。
6. 返回新版本后才更新前端已保存快照；保存期间产生的新编辑仍然标记为未保存。

不提供冲突强制覆盖入口。重新加载磁盘内容会先提示当前未保存编辑。原子替换保留普通权限；不承诺保留 ACL、扩展属性、硬链接关系和所有者信息，也不保证断电持久化。外部进程不遵守文件锁，最后一次检查与替换之间仍存在竞态；符号链接或目录被外部并发替换时也不提供安全隔离保证。当前面向可信本地项目。

路径由 Rust 统一校验：拒绝绝对路径与 `..`；规范化后必须仍在当前项目根内。指向项目内部的文件符号链接保存到真实目标，不替换链接本身；目录符号链接不展开，项目外链接不打开。

## 权限

仅加载目录选择插件、窗口能力与受控自定义命令；能力按 `window-*` 标签匹配所有项目窗口，没有 Shell、HTTP 或任意前端文件读写插件。生产 CSP 不加载远程脚本、字体或图像。所有本地文件内容由 CodeMirror 作为文本显示，不执行项目脚本。

## 当前规模限制

- 单文件可编辑上限 20 MiB，超过时只读预览开头 5 MiB；超过 1 MiB 字符的大文件禁用语法解析。
- 每个窗口最多 30 个打开或正在打开的标签。
- 单目录最多展示 10,000 项；超限明确报错，不返回伪完整列表。
- 文件树仅隐藏 `.git`、`node_modules`、`target` 和 `.DS_Store`，其余点文件正常显示。
- 文件树规则不等同于未来项目搜索规则；阶段一不解释 `.gitignore`。
- 暂不做列表虚拟化，长期性能目标在阶段四测量后验证。
