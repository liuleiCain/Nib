# 开发阶段与边界

## 阶段一 · 编辑器骨架

已实现真实项目打开、按需文件树、多标签编辑与保存、未保存提示、基础快捷键、深色主题与语言高亮。

本次额外实现的命令面板、字号和自动换行用于提供现有编辑操作的统一入口；不代表阶段三的搜索和持久化功能已完成。

已知限制：

- 尚无文件新增、重命名、删除及废纸篓入口。
- 项目目录监听、文件树与已打开标签实时刷新、自动保存已提前实现（见“阶段四提前交付”）；冲突时只提供重新加载，尚无对比合并界面。
- 配置、窗口/侧边栏尺寸不持久化；最近项目、打开的项目窗口及各项目标签已持久化（见“阶段三提前交付”）。
- 尚无未保存内容的崩溃恢复；不能将正常关闭提示视为备份机制。
- 不支持二进制预览、其他编码、混合换行、超大文件和项目外符号链接。
- 非 Unicode 的文件名会跳过并展示计数；中文、空格和换行等 Unicode 名称正常传递，不经 Shell。
- 无 Git 按钮、终端、LSP、补全、重构、调试器；没有占位操作。
- 中文输入法组合输入需要在真实系统输入法下人工验收，自动化输入中文不等同于 IME 验证。
- 尚未建立冷启动、总内存、长列表和大仓库性能基线。

## 阶段三提前交付 · 项目与会话

应用户要求提前实现：同时打开多个项目（macOS 为同一窗口顶部的原生项目标签，其他平台为独立窗口）、最近项目、启动时恢复上次打开的项目窗口及各项目标签。未保存内容恢复、窗口尺寸与位置、设置持久化仍属阶段三。

## 阶段四提前交付 · 实时刷新与自动保存

应用户要求（AI 写代码场景下页面需实时为最新）提前实现：项目目录监听与事件合并、文件树与已打开标签实时刷新、干净与未保存文件的外部变化区分处理，以及类似 GoLand 的自动保存。冲突对比界面、大仓库下的监听性能测量仍属阶段四。

## 阶段二 · Git 核心闭环

仓库识别、分支、NUL 分隔状态解析、独立展示暂存/工作区/未跟踪、统一 Diff、暂存与取消暂存、仅提交暂存区。Git 写操作按仓库串行，参数数组调用，保留错误时的提交输入。

## 阶段三 · 日常使用

提交记录与详情、分支创建/切换、Fetch/Push、仅快进 Pull、文件快速打开、尊重 `.gitignore` 的可取消项目搜索、设置与未保存恢复、窗口尺寸恢复、文件管理（最近项目与标签恢复已提前交付）。

## 阶段四 · 稳定性与性能

冲突对比与合并界面、大仓库监听性能测量、长任务取消、列表虚拟化、大文件/仓库/Diff 测量、启动与内存基线、macOS 分发签名/公证、Windows/Linux 实机构建。

数据安全问题、范围变更或基础架构调整需单独讨论；后续阶段不在本次交付中宣称完成。
