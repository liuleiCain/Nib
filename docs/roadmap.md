# 开发阶段与边界

## 阶段一 · 编辑器骨架

已实现真实项目打开、按需文件树、多标签编辑与保存、未保存提示、基础快捷键、深色主题与语言高亮。

本次额外实现的命令面板、字号和自动换行用于提供现有编辑操作的统一入口；搜索和持久化在阶段三完成。

已知限制：

- 文件新增、重命名、删除到废纸篓已随阶段二实现。
- 项目目录监听、文件树与已打开标签实时刷新、自动保存已提前实现（见“阶段四提前交付”）；外部修改冲突可打开双栏对比并手动合并。
- 设置、窗口与侧边栏尺寸、未保存内容恢复已在阶段三实现。
- 不支持二进制预览、其他编码、混合换行和项目外符号链接；超过 20 MiB 的文本只读预览开头 5 MiB。
- 非 Unicode 的文件名会跳过并展示计数；中文、空格和换行等 Unicode 名称正常传递，不经 Shell。
- 无终端、LSP、补全、重构、调试器；没有占位操作。
- 中文输入法组合输入需要在真实系统输入法下人工验收，自动化输入中文不等同于 IME 验证。
- 尚未建立冷启动、总内存、长列表和大仓库性能基线。

## 阶段三提前交付 · 项目与会话

应用户要求提前实现：同时打开多个项目（macOS 为同一窗口顶部的原生项目标签，其他平台为独立窗口）、最近项目、启动时恢复上次打开的项目窗口及各项目标签。未保存内容恢复、窗口尺寸、设置持久化随后在阶段三实现；窗口位置不记录。

## 阶段四提前交付 · 实时刷新与自动保存

应用户要求（AI 写代码场景下页面需实时为最新）提前实现：项目目录监听与事件合并、文件树与已打开标签实时刷新、干净与未保存文件的外部变化区分处理，以及类似 GoLand 的自动保存。

后续已补充实时变更窗口（只展示文件与 Diff，不记录 Agent 会话）、跟随最新变化开关、标签 Git 状态着色和批量关闭菜单，以及外部修改冲突双栏对比。冲突对比左侧为最新磁盘内容，右侧为可编辑的合并草稿，可按块采用磁盘内容、保留草稿返回或使用磁盘版本；合并保存沿用版本校验。磁盘侧随相关文件事件刷新，右侧草稿进入原标签及现有恢复机制，处理期间暂停自动保存。不自动合并，也不代替 Git 冲突的三方合并界面；磁盘文件超过 5 MiB 或不可读时只保留草稿并提示。

已在 macOS debug 应用中完成 1,000 个文件批量修改及同一文件 600 次连续写入的短时验证，见验证记录。真实大型仓库、长时间运行、应用与 WebView 总占用仍需测量。

## 阶段二 · Git 核心闭环（已实现）

按用户选择采用 GoLand 默认的勾选提交模式，替代原计划的“暂存 / 取消暂存、仅提交暂存区”：变更列表合并展示相对 HEAD 的修改，勾选文件后 `git commit --only` 只提交这些文件，不改变其他文件的暂存状态。

已实现：仓库与分支识别（含仓库子目录、非仓库、Git 不可用）、NUL 分隔状态解析、变更与未跟踪分组、左右对比与统一 Diff、行号旁变更标记、文件树着色、状态栏分支、勾选提交、Git 操作后的实时刷新。Git 写操作按仓库串行，参数数组调用，提交失败保留输入。

已知限制：

- 不单独展示或操作暂存区；同一文件已暂存和未暂存的部分合并为一条变更，提交时整体提交工作区内容。
- Diff 内容只读，不能在 Diff 中直接编辑；可按块回滚为 HEAD 版本，但不支持按行或按块提交。
- 文件树右键可回滚整个文件或目录的变更（修改会被丢弃，确认后执行），由用户确认后纳入阶段二；不提供 Reset、Clean。
- 拣选、还原等进行中时只能在终端完成（合并与变基见阶段三）；冲突文件不提供图形化解决界面。
- 变更列表最多 5,000 个文件，未做虚拟化；Diff 单侧超过 5 MiB 不显示。
- 子模块只显示状态，不展示其内部变更。

## 阶段三 · 日常使用

已实现（Git 部分）：当前分支提交记录分页（作者、时间、短哈希、引用标记）、提交详情与只读文件 Diff；本地与远程分支列表（搜索过滤）、分支操作菜单（切换、从任意分支新建、检出远程分支、重命名、删除本地或远程分支）、远程地址与上游信息、远程仓库管理（添加、修改地址、重命名、删除）；Fetch、Push（推送前确认框列出待推送的提交与文件，无上游时选择远程并设置上游）、仅快进 Pull；应用户要求加入合并与变基（把其他分支合并到当前分支、把当前分支变基到其他分支，冲突后标记已解决、完成合并 / 继续变基、跳过提交、中止），改变了原定“第一版不实现 Merge/Rebase”的范围。

Git 部分的已知限制：

- 提交记录为线性列表（`git log` 默认顺序），不绘制分支图；只显示当前 HEAD 的历史，不能按作者、路径或信息筛选，不支持查看其他分支的记录。
- 合并提交只与第一个父提交比较。
- 分支菜单不提供与当前分支比较、检出并变基、交互式变基、压缩合并（squash）、拣选；非当前分支不能单独拉取或推送；不提供标签管理。
- 合并与变基只在已跟踪文件没有未提交修改时开始（不提供 Stash），保证中止能完整恢复；合并信息使用 Git 默认格式，不能在合并前编辑。
- 冲突只能在编辑器中直接修改冲突标记，没有三方合并视图，也没有“接受我方 / 对方”的一键操作；标记为已解决时会检查残留的冲突标记。项目是仓库子目录时，项目外的冲突文件需在终端处理。
- 变基会重写提交；已推送的提交变基后无法普通推送，Nib 不提供强制推送。
- Pull 只快进，分叉时可在分支弹窗中合并或变基上游分支；不提供强制推送。
- 远程操作不能中途取消，只能等待 180 秒超时；需要交互式认证（输入密码、确认主机密钥）时直接失败。
- 分支列表与 ↑↓ 数来自本地的远程分支记录，获取后才会更新。
- 推送确认框中的提交按本地记录的远程分支计算，确认前不会自动获取；新分支按该远程已获取的所有分支排除，远程可能已有其中部分提交。最多列出 1,000 个提交，不能只推送其中一部分，也不能在框内修改提交信息或推送标签。
- 远程仓库管理不能单独设置推送地址（`pushurl`）或多个地址，也不能编辑 fetch refspec；修改地址后不会自动获取。

已实现（搜索、设置与恢复）：Cmd/Ctrl+P 快速打开（模糊匹配、`路径:行号`）；Cmd/Ctrl+Shift+F 项目搜索（按文件分组、可取消、限制结果数、排除 `.git`、默认尊重 `.gitignore`，可选区分大小写、全词、正则、包含被忽略的文件）；命令面板补充快速打开、项目搜索、设置、字号、缩进、复制路径、访达显示、恢复未保存内容；设置框（工具栏齿轮、Cmd/Ctrl+,）：字体、字号、缩进宽度、自动换行、自动保存、变更列表分组、Diff 视图（`~/.nib/settings.json`，带版本号，经 Rust 读写，多窗口同步）；窗口尺寸、侧边栏宽度、侧边栏显示与面板恢复，各项目文件树展开目录恢复；未保存内容的本地恢复（`~/.nib/recovery/`，与配置、会话和项目文件分开存储）。

搜索、设置与恢复的已知限制：

- 快速打开最多列出 50,000 个文件，每次打开时重新遍历，不建立索引；只按文件名和路径匹配，不支持按符号跳转。
- 项目搜索只搜索磁盘内容，不含未保存的编辑；不支持替换、文件类型或目录过滤、多行匹配；结果约 2,000 处、单文件 200 处后截断，超过 5 MiB 或非 UTF-8 的文件不搜索；正则语法为 Rust `regex`（不支持回溯引用与环视）。
- 设置只有编辑器字体、字号、缩进宽度、自动换行、自动保存及两项 Git 显示；系统字体列表在首次打开设置时读取一次，新装的字体需重启 Nib；缩进固定使用空格，不按项目或语言区分，不读取 `.editorconfig`。
- 窗口只记录尺寸，不记录位置和最大化状态；多个窗口共用最近一次的尺寸。
- 未保存内容最多每 1.5 秒写入一次，异常退出可能丢失最后这段编辑；超过约 150 万字符的文件、只读预览的大文件不写恢复数据；恢复时若磁盘版本已变化，会暂停自动保存，可通过「对比并处理」核对内容；文件已删除的恢复数据只能到 `~/.nib/recovery/` 手动取回。

## 阶段四 · 稳定性与性能

外部修改冲突的双栏对比与手动合并已交付，并完成一轮短时连续写入验证。剩余：大仓库监听性能测量、长任务取消、列表虚拟化、大文件/仓库/Diff 测量、启动与应用及 WebView 总内存基线、长时间稳定性、macOS 分发签名/公证、Windows/Linux 实机构建。

数据安全问题、范围变更或基础架构调整需单独讨论；后续阶段不在本次交付中宣称完成。
