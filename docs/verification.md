## 原生窗口行为

在独立的临时项目中，通过真实 Tauri 窗口验证：

- 展示真实文件树，打开 Go 与 Markdown 文件并切换标签。
- 在中文文件名的 Go 文件中输入中文文本，执行 Cmd+S，核对磁盘内容，关闭标签再打开，内容一致。
- 修改后执行 Cmd+W，出现保存、放弃和返回编辑提示；返回后编辑内容及未保存标记保留。
- 标签切换后执行 Cmd+Z / Cmd+Shift+Z，撤销与重做历史保留，撤销至已保存内容时未保存标记消失。
- 外部程序修改磁盘文件后执行保存，界面显示冲突，编辑器内容和外部磁盘内容均保留；重新加载前再次提示未保存内容，选择放弃后读到外部版本。

上述中文文本输入使用自动化粘贴，不能替代真实中文输入法的候选词、组合输入和确认操作验收。

## 阶段二 Git 验证

验证日期：2026-10-30，Git 2.50.1（Apple Git-155）。

以下命令均通过：`npm run typecheck`、`npm run format:check`、`npm run build`、`cargo fmt --check`、`cargo clippy -- -D warnings`、`npm run desktop:build -- --bundles app`。

临时 Rust 程序直接引入项目的 `git`、`workspace` 和 `error` 模块，在系统临时目录的真实仓库中运行，再用 Git CLI 核对，程序与仓库验证后删除：

- 状态解析：修改、CRLF 文件修改、`git mv` 重命名（含原路径）、删除、二进制修改、同一文件已暂存又有未暂存修改（合并为一条修改）、未跟踪的中文空格路径、文件名含换行、文件名为 `*.json`，与 `git status` 一致。
- Diff 内容：修改、CRLF（统一为 LF）、重命名读原路径、删除（工作区侧不存在）、新文件（HEAD 侧不存在）、二进制、通配字符和换行文件名；越界路径被拒绝。
- 勾选提交：勾选修改、重命名（新旧路径）、删除、三个未跟踪文件，提交后 `git show --stat` 正好包含这 6 项；未勾选的 `bin.dat`、`crlf.txt` 和暂存状态混合的 `staged_only.txt` 保持原状（`MM` 不变）；中文多行提交信息及以 `#` 开头的正文行完整保留。
- 空提交信息被拒绝；`pre-commit` 钩子拒绝时返回钩子的错误输出，勾选的未跟踪文件恢复为未跟踪。
- 文件操作：新建中文空格文件名与目录成功；同名、含 `/`、`.git`、`..` 父目录被拒绝。重命名已跟踪文件和目录为 `R`（`git mv`），未跟踪文件直接改名，同名冲突被拒绝，只改大小写成功。移到废纸篓后文件消失；符号链接只移走链接本身，`/etc` 不受影响；项目根目录和旧项目 id 被拒绝。
- 回滚：一次回滚修改、删除、重命名、新增与目录内重命名，修改与删除内容恢复为 HEAD，重命名恢复原名且新路径消失，新增文件保留为未跟踪，其他变更不受影响；未跟踪文件和无变更文件被拒绝。
- 添加到 .gitignore：未跟踪文件、目录（加 `/`）、含 `*`、`[` 的文件名写入转义后的锚定规则，重复添加不重复写入，CRLF 文件沿用 CRLF；已跟踪文件和含已跟踪文件的目录被拒绝；`.gitignore` 为符号链接时拒绝写入。
- 加入版本控制：中文空格路径、`*.json`（字面匹配，未带上同目录的 `x.json`）、含换行的文件名加入后为 `A`，已修改的 `base.txt` 未被暂存，HEAD 未产生新提交；空列表、`..` 越界、旧项目 id 被拒绝；`.gitignore` 忽略的文件返回 Git 的说明。
- 恢复已删除文件：删除中文空格路径文件后恢复成功，内容与 `git checkout HEAD -- 路径` 一致（本机 `core.autocrlf=input` 时 CRLF 文件按 Git 规则检出为 LF）；`git rm` 暂存删除的 `*.json` 恢复后 `git status` 干净；文件已存在、HEAD 中不存在、`..` 越界、绝对路径、旧项目 id、合并进行中均被拒绝且不改动文件。
- 仓库子目录作为项目：只列出子目录内的变更，路径相对项目根目录，HEAD 版本正确；非仓库目录返回“非 Git 项目”；切换项目后旧请求被拒绝。
