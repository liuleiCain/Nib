## 原生窗口行为

在独立的临时项目中，通过真实 Tauri 窗口验证：

- 展示真实文件树，打开 Go 与 Markdown 文件并切换标签。
- 在中文文件名的 Go 文件中输入中文文本，执行 Cmd+S，核对磁盘内容，关闭标签再打开，内容一致。
- 修改后执行 Cmd+W，出现保存、放弃和返回编辑提示；返回后编辑内容及未保存标记保留。
- 标签切换后执行 Cmd+Z / Cmd+Shift+Z，撤销与重做历史保留，撤销至已保存内容时未保存标记消失。
- 外部程序修改磁盘文件后执行保存，界面显示冲突，编辑器内容和外部磁盘内容均保留；重新加载前再次提示未保存内容，选择放弃后读到外部版本。

## 阶段三 Git 验证（提交记录、分支与远程）

验证日期：2026-10-30，Git 2.50.1（Apple Git-155）。

以下命令均通过：`npm run typecheck`、`npm run format:check`、`npm run build`、`cargo fmt --check`、`cargo clippy -- -D warnings`、`npm run desktop:build -- --bundles app`。

临时 Rust 程序直接引入项目的 `git`、`workspace`、`filesystem` 和 `error` 模块，在系统临时目录中用本地裸仓库作为远程运行，程序与仓库验证后删除：

- 提交记录：项目为仓库子目录（含中文和空格路径）时只列出相关提交；引用标记识别当前分支与标签；`skip` 分页正确；尚无提交的仓库返回空列表。
- 提交详情：多行提交信息完整；子目录内的重命名显示为 `R` 并带原路径，新增为 `A`；根提交按 `--root` 列出。历史 Diff 中重命名两侧取新旧路径，根提交的父侧为不存在。`--all`、`HEAD` 等非十六进制哈希被拒绝。
- 分支：列表含上游、领先/落后数（分叉时 ↑1 ↓1），当前分支在前；空仓库返回当前分支名、无本地分支和远程。含空格、以 `-` 开头的名称被拒绝；已存在的分支、尚无提交时新建被拒绝；含 `/` 和中文的分支名创建并切换成功；不存在的分支切换被拒绝；未提交修改与目标分支冲突时由 Git 拒绝，文件未被覆盖。
- 分支操作：远程名含 `/`（`up/stream`）时远程分支正确拆分；检出远程分支后上游为该远程分支，再次检出直接切换，同名分支跟踪其他远程时被拒绝；不存在的远程分支、以 `--` 开头的远程名被拒绝。从远程分支新建不设置上游，从本地分支新建切换到其提交；`HEAD~1`、`refs/heads/--orphan` 等起点被拒绝。重命名当前分支成功，目标已存在被拒绝，重命名后上游保留。删除当前分支被拒绝；已合并的分支直接删除；未合并时返回 `NOT_MERGED` 且分支保留，强制删除成功。删除远程分支后远程仓库与本地远程分支记录同时移除，再删除时说明不存在。
- 远程：没有上游时拉取说明原因、推送返回 `NO_UPSTREAM`；指定远程推送后上游为 `origin/main`；随后拉取为“已是最新”。另一个克隆推送后获取成功、拉取快进 1 个提交；双方各有新提交时推送被拒绝并提示先拉取，拉取说明已分叉及双方提交数，不做合并；上游分支在远程删除后推送按原配置重建远程分支；没有远程时获取说明原因。
- 合并：已跟踪文件有未提交修改时拒绝（返回 `DIRTY`，未跟踪文件不影响）；与当前分支自身、短名 `feat`、不存在的引用被拒绝。无冲突时生成两个父提交的合并提交，信息为 `Merge branch 'feat'`；再次合并为“已是最新”；落后时快进。冲突时返回冲突文件并保持合并中；有冲突时继续仍返回暂停；文件仍含冲突标记时标记返回 `CONFLICT_MARKERS`，确认后可强制标记；非冲突文件、项目外路径被拒绝；中止后 HEAD 与工作区恢复干净。解决后标记、再编辑同一文件，完成合并的提交包含最后的内容，之后工作区干净。合并中跳过被拒绝；合并中再合并、切换分支被拒绝；状态返回 `operation: 合并`。
- 变基：冲突时停下、中止后回到原提交；解决冲突后继续，分支保持为 `feat`，历史为线性（`feat c | feat a | main a | init`）；已包含目标时为“已是最新”；跳过冲突提交后分支与 `main` 相同。以 `refs/remotes/origin/main` 为目标无冲突变基后，相对上游领先 1、落后 0。
- 冲突类型与路径：项目为仓库子目录时，冲突文件路径相对项目根目录，项目外文件显示为 `../a.txt`；修改 / 删除冲突中删除文件后标记为已解决，完成合并后文件从 HEAD 移除。`pre-merge-commit` 钩子失败时无冲突也停在合并中，返回钩子的说明；移除钩子后完成合并成功。
- 推送确认：空仓库、没有远程、游离 HEAD 时预览说明原因；没有上游时默认 `origin`（远程依次为 `zeta`、`origin`），可指定 `zeta`，不存在的远程被拒绝，均标记为新分支并列出全部提交（新的在前）。预览后再提交一次，用旧的 HEAD 推送返回 `PUSH_CHANGED`，裸仓库中没有任何分支。推送设置上游后预览为 0 个；再提交 2 次后列出这 2 个。从 `main` 新建 `feat` 并提交 1 次，预览按 `origin` 已有的分支排除，列出 3 个。`feat` 推送后在远程删除并清理记录，预览仍以 `origin/feat` 为目标、标记为新分支；推送重建远程分支后预览为 0 个。
- 远程仓库管理：添加 `origin`（名称两侧空格去除）后地址与 Git 配置一致；重复名称、含空格或以 `-` 开头的名称、以 `-` 开头的地址（`--upload-pack=…`）、含 `***` 的隐藏密码地址、空地址被拒绝。添加后推送设置上游、获取成功。改为含令牌的 HTTPS 地址后列表显示为 `***`，不存在的远程改地址被拒绝。重命名为 `up` 后上游变为 `up/main`，远程分支记录改为 `refs/remotes/up/…`；重命名为已存在的名称被拒绝。合并进行中仍可添加远程。删除后远程配置、远程分支记录和上游一并移除，裸仓库中的分支不受影响；再次删除说明不存在。

另用 Git CLI 核对了 `log -z`、`diff-tree --relative`、`for-each-ref` 与 `upstream:track`、`check-ref-format` 的实际输出格式，以及 HTTPS 地址中的密码不会出现在 Git 错误输出中。

尚未验证：真实窗口中的提交记录面板、分支弹窗（搜索、操作菜单的位置与键盘操作、删除确认框）、提交 Diff 标签、新建分支输入框、拉取/推送按钮和远程选择菜单的显示与交互；切换分支、拉取后已打开标签的刷新；真实网络远程（GitHub 等）的 SSH / HTTPS 认证失败提示、凭据助手和 pre-push 钩子；网络超时。合并、变基的分支菜单项、变基确认框、提交面板冲突横幅与按钮、标记已解决和残留冲突标记确认框在真实窗口中的显示与交互，以及合并、中止后已打开标签的刷新；`rebase-apply`（`am` 后端）、多次连续冲突的变基、rerere 均未验证。
