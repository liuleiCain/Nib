# Nib 轻量代码编辑器开发大纲

## 一、产品定位

开发一款名为 **Nib（笔尖）** 的轻量桌面代码编辑器，核心特点是：

- **极简**：界面克制，减少常驻面板和低频功能。
- **轻量**：控制启动时间、内存占用和后台任务数量。
- **便捷**：打开项目即可编辑，常用 Git 操作直观可见。
- **流畅**：文件读取、Git 操作、搜索等任务不阻塞界面。

产品以基础代码编辑和 Git 可视化为核心。参考 GoLand 的 Git 操作流程，结合 Sublime Text、Zed 的简洁布局，自行设计界面，不直接复制其他产品的视觉资产。

第一阶段面向个人开发者，优先支持 macOS，同时保持 Windows、Linux 的架构兼容性。

## 二、技术选型

| 模块        | 方案                             |
| ----------- | -------------------------------- |
| 桌面框架    | Tauri 2                          |
| 后台语言    | Rust                             |
| 前端        | React + TypeScript               |
| 构建工具    | Vite                             |
| 代码编辑器  | CodeMirror 6                     |
| UI 基础组件 | 按需使用 Radix UI / shadcn/ui    |
| 图标        | Lucide                           |
| Git 集成    | 调用本机 Git CLI                 |
| 包管理      | npm                              |
| 配置存储    | 本地配置文件，通过 Rust 统一读写 |

补充约束：

- 尽量使用稳定版本，初始化时检查依赖之间的兼容性。
- 按需引入组件，避免直接安装大型组件库的完整功能。
- 前端状态优先使用 React 自身能力，出现明确需求后再引入状态管理库。
- 第一阶段不引入数据库、插件系统和完整项目索引。
- 优先使用项目内既有工具，新增依赖需有明确用途。

## 三、第一版功能范围

### 1. 项目与文件管理

- 打开本地文件夹作为项目。
- 展示最近打开的项目。
- 文件树按需加载，支持展开和折叠。
- 新建文件、新建文件夹、重命名。
- 删除文件优先移入系统废纸篓。
- 区分文件树隐藏规则与搜索忽略规则；搜索默认尊重 `.gitignore`。
- 文件发生外部变化时更新界面。
- 已打开文件被外部修改时，根据是否存在未保存编辑提示处理。

第一版一个窗口只管理一个项目。

### 2. 基础代码编辑

- 多标签页。
- 修改未保存状态提示。
- 保存、关闭标签页、关闭其他标签页。
- 撤销、重做。
- 查找、替换。
- 行号、当前行高亮、括号匹配、自动缩进。
- 字体大小调整、自动换行切换。
- 支持常见文本文件，优先提供 Go、Rust、JavaScript、TypeScript、JSON、Markdown、YAML 的语法高亮。
- 二进制文件显示说明，避免当作普通文本加载。
- 默认支持 UTF-8，其他编码暂时给出明确提示。
- 保存时尽量保留原文件换行风格，避免无关的整文件变化。

第一版不实现语义补全、复杂重构和调试器，后续通过 LSP 逐步扩展。

### 3. Git 可视化

Git 是第一版的重点，按以下范围实现。

**仓库状态**

- 识别当前项目所属仓库。
- 展示当前分支。
- 展示已暂存、未暂存和未跟踪文件。
- 同一个文件可以分别出现在已暂存和未暂存列表中。
- 正确展示新增、修改、删除、重命名和冲突状态。
- 非 Git 项目仍可正常编辑文件。

**变更查看**

- 点击文件打开 Diff。
- 第一版优先实现统一 Diff，后续增加左右对比。
- 区分未暂存变更与已暂存变更。
- 对二进制变更、大 Diff 和不支持的内容显示明确说明。
- Diff 结果支持取消、截断提示与按需加载。

**暂存与提交**

- 单文件暂存、取消暂存。
- 全部暂存、全部取消暂存。
- 输入提交信息并提交。
- 提交前展示将要提交的内容范围。
- 提交失败时保留输入内容，并展示可理解的错误信息。

第一版提交操作仅提交暂存区内容。编辑器中未保存的内容需要明确标识，避免用户误以为已经参与 Git 操作。

**提交记录**

- 分页展示当前分支提交记录。
- 展示提交信息、作者、时间和短哈希。
- 点击提交查看文件列表与变更。
- 第一版使用线性列表，提交关系图后续实现。

**分支与远程操作**

- 查看本地分支。
- 创建和切换本地分支。
- 展示远程地址与上游信息。
- 支持 Fetch、Push。
- 第一版 Pull 仅支持快进更新；存在分叉时解释原因。
- 凭据沿用本机 Git 配置，不自行保存账号密码。
- 无法交互完成认证时给出明确提示，禁止后台无限等待。

第一版暂不实现：

- 按区块或按行暂存。
- 图形化冲突解决。
- Merge、Rebase、Cherry-pick。
- Stash 管理。
- 强制推送。
- 丢弃变更、Reset、Clean 等高风险操作。
- 子模块与多工作区的专门管理界面。

遇到上述场景时，应保留已有状态并明确说明限制。

### 4. 搜索与快捷操作

- 当前项目文件名快速搜索。
- 项目文本搜索，结果按文件分组。
- 搜索可取消，并限制一次展示的结果数量。
- 排除 `.git`，默认尊重忽略规则。
- 命令面板，集中提供常用操作。
- 快捷键适配 macOS 的 Command 与其他系统的 Ctrl。

默认快捷键：

| 操作         | macOS         | Windows / Linux |
| ------------ | ------------- | --------------- |
| 快速打开文件 | `Cmd+P`       | `Ctrl+P`        |
| 命令面板     | `Cmd+Shift+P` | `Ctrl+Shift+P`  |
| 保存         | `Cmd+S`       | `Ctrl+S`        |
| 当前文件查找 | `Cmd+F`       | `Ctrl+F`        |
| 项目搜索     | `Cmd+Shift+F` | `Ctrl+Shift+F`  |
| 关闭标签页   | `Cmd+W`       | `Ctrl+W`        |
| 切换侧边栏   | `Cmd+B`       | `Ctrl+B`        |

### 5. 设置与会话恢复

- 第一版提供一套深色主题。
- 支持字体、字号、缩进宽度、自动换行设置。
- 记住窗口尺寸、侧边栏宽度、最近项目和已打开文件。
- 未保存内容需要本地恢复机制，避免异常退出后丢失。
- 配置文件包含版本号，为后续迁移预留空间。

## 四、界面设计

### 整体布局

```text
┌────────────────────────────────────────────────────────┐
│ Nib   项目名称                  搜索 / 命令       窗口控制 │
├──────────────┬─────────────────────────────────────────┤
│ 文件  Git    │ main.go   config.go                      │
│              ├─────────────────────────────────────────┤
│ 文件树       │                                         │
│ 或           │               编辑 / Diff                │
│ Git 变更列表 │                                         │
│              │                                         │
├──────────────┴─────────────────────────────────────────┤
│ ⎇ main   ↑1 ↓0                  Go  UTF-8   行 12，列 8 │
└────────────────────────────────────────────────────────┘
```

### 设计原则

- 文件和 Git 共用左侧侧边栏，通过顶部入口切换。
- 编辑器和 Diff 使用主内容区域。
- 提交记录按需打开，避免常驻占用空间。
- 第一版不内置终端；后续按需求增加。
- 使用中性灰、一种低饱和强调色和统一线性图标。
- 提取颜色、字号、间距、边框等设计变量。
- 减少大圆角、装饰性卡片、阴影和动画。
- 高频操作直接可见，低频操作进入菜单或命令面板。
- 兼顾键盘操作、焦点状态和中文输入法。
- 优先使用系统窗口能力，避免为自定义标题栏引入额外复杂度。

## 五、架构设计

采用清晰的前后端职责划分。

**前端负责：**

- 界面渲染。
- CodeMirror 编辑器集成。
- 标签页和用户交互状态。
- Git 状态、Diff、提交记录的展示。
- 调用后台命令，订阅后台事件。
- 加载、空状态、失败和取消状态的呈现。

**Rust 后台负责：**

- 文件系统访问和安全保存。

- 文件监听与事件合并。

## 六、Git 与文件操作的关键约束

### Git 调用

- 使用进程 API 和独立参数数组调用 Git。
- 禁止将用户输入拼接进 Shell 命令。
- 文件路径与 Git 参数明确分隔。
- 优先使用支持机器解析的输出，例如状态查询采用 NUL 分隔格式。
- 正确处理带空格、中文、换行和特殊字符的文件名。
- 同一仓库的写操作串行执行。
- 操作完成后刷新相关状态，防止旧结果覆盖新结果。
- 读取操作支持取消和超时；写操作的超时处理需要明确结果，不能简单重试。
- 日志、文件列表和 Diff 均限制输出规模。
- 检测 Git 是否可用，并提供安装或配置提示。

### 文件操作

- 文件写入采用安全保存策略，避免中途失败损坏内容。
- 保存时考虑符号链接、文件权限和外部修改。
- 文件监听按项目范围启用，合并短时间内重复事件。
- 配置数据、恢复内容和项目文件分别存储。
- Tauri 权限按实际功能授予，避免开放任意 Shell 执行能力。

## 七、性能要求

性能优化必须基于测量，记录环境与项目规模。

重点要求：

- 首屏优先显示窗口和基本界面，项目数据随后加载。
- Git、搜索、文件扫描等任务不阻塞界面。
- 文件树、提交列表、搜索结果按需加载。
- 长列表使用虚拟化。
- 避免切换标签页时重复创建编辑器和重新读取文件。
- 控制编辑器实例与缓存数量。
- 大文件进入降级模式，减少高亮和其他昂贵功能。
- 文件监听采用事件合并和防抖。
- 不通过高频轮询持续刷新仓库。
- 空闲时避免持续运行后台任务。

建议先以以下指标作为优化目标，建立基线后再调整：

| 指标                     | 初始目标                                                    |
| ------------------------ | ----------------------------------------------------------- |
| 参考机器上冷启动到可交互 | 2 秒以内                                                    |
| 已加载文件的标签切换     | 100 毫秒以内                                                |
| 常规输入与滚动           | 无明显卡顿                                                  |
| 空闲后台活动             | 无持续扫描，无明显持续 CPU 占用                             |
| 内存                     | 统计应用及相关 WebView 进程总占用，优先控制稳定值并排查增长 |

不要提前承诺未经验证的固定内存数字。分别记录空窗口、打开项目、打开多个文件和显示大 Diff 时的占用。

## 八、开发阶段与验收

### 阶段一：可运行的编辑器骨架

完成：

- 初始化 Tauri、React、TypeScript、CodeMirror。
- 基础主题和布局。
- 打开项目、文件树。
- 打开文件、多标签编辑和保存。
- 未保存提示。
- 基础快捷键。

验收：可以打开真实项目、编辑并保存文件；中文输入正常；重新打开文件内容正确。

### 阶段二：Git 核心闭环

完成：

- 仓库识别和分支展示。
- 已暂存、未暂存、未跟踪列表。
- Diff 查看。
- 暂存、取消暂存。
- 提交。

验收：可以在 Nib 中完成“修改文件 → 查看 Diff → 暂存 → 提交”，结果与 Git CLI 一致。

### 阶段三：日常使用能力

完成：

- 提交记录和提交详情。
- 分支创建与切换。
- Fetch、Push、仅快进 Pull。
- 文件快速打开、项目搜索、命令面板。
- 设置持久化与会话恢复。

验收：可以用于小型真实项目的日常编辑和基本 Git 操作；失败信息明确，未保存内容可恢复。

### 阶段四：稳定性与性能

完成：

- 大仓库、大文件、大 Diff 的处理。
- 文件监听和外部修改处理。
- 后台任务取消和并发控制。
- 启动与内存基线记录。
- macOS 打包。
- Windows、Linux 构建兼容性检查，并如实记录实际验证范围。

验收：无已知数据丢失问题，长任务不阻塞交互，性能结果有可复现记录。

## 九、验证重点

优先验证真实行为：

- 文件编辑、保存、撤销、关闭与恢复。
- 中文输入法与中文路径。
- 外部修改与未保存内容冲突。
- 文件新增、删除、重命名和二进制变更。
- 同一文件同时存在已暂存与未暂存内容。
- 提交失败、Git 不可用、认证失败、网络失败。
- 分支切换被未提交变更阻止。
- 大量文件和较长提交历史下的响应。
- 快速切换项目后，不出现前一个项目的迟到结果。

遵守仓库中的 `AGENTS.md`。若规则禁止新增测试文件，则使用已有检查和临时目录验证，验证完成后清理临时产物。

## 十、交付要求

- 提供可运行的项目源码。
- README 包含环境要求、启动、构建、打包命令。
- 说明本机 Git 依赖。
- 记录架构、主要功能、快捷键与已知限制。
- 每个阶段完成后执行相应格式检查、类型检查和构建验证。
- 不用静态假数据代替已经宣称完成的功能。
- 未实现功能应明确标识，不提供无作用按钮。
- 不擅自创建 Git commit。
- 先完成阶段一，再按阶段推进，确保每个阶段都有可运行结果。

**请先检查当前目录和开发环境，建立 Nib 项目并完成阶段一。在实施中自行处理常规技术选择；遇到会影响数据安全、产品范围或基础架构的重大问题时再提出确认。**
